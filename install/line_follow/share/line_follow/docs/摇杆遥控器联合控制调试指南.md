# 摇杆+遥控器联合调试总指南

本文档是当前仓库唯一保留的调试说明，覆盖：

- 编译与部署
- 摇杆 + 长按遥控联合控制链路
- 巡线视觉与电机驱动联调
- systemd 自启动
- 常见故障排查

当前唯一推荐入口：

```bash
ros2 launch line_follow joystick_remote_hybrid.launch.py
```

## 1. 当前系统结构

联合版控制关系如下：

1. `joystick_drive_node` 读取摇杆 GPIO，发布 `/joystick_motor_speed_cmd`
2. `joystick_drive_node` 同时发布 `/joystick_override_active`
3. `remote_long_press_start_line_follow_node` 读取遥控器 GPIO
4. 长按遥控器前进键进入手动前进，发布 `/motor_speed_cmd`
5. 长按遥控器后退键进入巡线，控制 `/line_follow_motor_model_node enabled`
6. `line_follow_angle_node` 处理图像，输出 `/line_follow/line_angle_deg`
7. `line_follow_motor_model_node` 将角度转成 `/motor_speed_cmd`
8. `motor_driver_control_node` 按优先级执行：
   - `override_active=true` 时执行 `/joystick_motor_speed_cmd`
   - `override_active=false` 时执行 `/motor_speed_cmd`

结论：

- 摇杆优先级最高
- 摇杆松手后，控制权回到遥控器或巡线
- 不允许系统里同时存在多套同名节点

## 2. 引脚与默认动作

### 2.1 摇杆引脚

RDK 40Pin 物理针脚：

- `11` -> 前进
- `15` -> 后退
- `13` -> 左转
- `16` -> 右转

默认摇杆速度：

- 前进：`[600.0, -600.0]`
- 后退：`[-600.0, 600.0]`
- 左转：`[-600.0, -600.0]`
- 右转：`[600.0, 600.0]`

### 2.2 遥控器引脚

- `31` -> 长按前进，进入手动前进
- `29` -> 长按后退，进入自动巡线

### 2.3 去抖参数

联合 launch 默认：

- `debounce_activate_count:=5`
- 遥控器 `debounce_deactivate_count:=1`
- 摇杆 `debounce_deactivate_count:=8`

如果 GPIO 漂浮或误触发，优先增大去抖，再排查硬件上拉、接地和线缆干扰。

## 5. systemd 自启动

当前只保留联合版服务，推荐服务名：

- `line-follow-hybrid.service`

启动脚本 `/userdata/dev_ws/start_line_follow_hybrid.sh`：

```bash
#!/bin/bash
set -e

source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash

exec ros2 launch line_follow joystick_remote_hybrid.launch.py
```

服务文件 `/etc/systemd/system/line-follow-hybrid.service`：

```ini
[Unit]
Description=Line Follow Hybrid Service
After=network.target
Wants=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/userdata/dev_ws
ExecStart=/userdata/dev_ws/start_line_follow_hybrid.sh
Restart=always
RestartSec=2
KillMode=control-group
TimeoutStopSec=10

[Install]
WantedBy=multi-user.target
```

启用：

```bash
systemctl daemon-reload
systemctl enable line-follow-hybrid.service
systemctl start line-follow-hybrid.service
```

状态与日志：

```bash
systemctl status line-follow-hybrid.service
journalctl -u line-follow-hybrid.service -f
```

## 6. 推荐调试流程

固定按这个顺序调，不要跳步。

### 6.1 第一步：只看 GPIO 输入

检查摇杆：

```bash
ros2 run line_follow joystick_drive_node --ros-args -p debug_inputs_only:=true
```

检查物理引脚对应关系：

```bash
cd /userdata/dev_ws/src/originbot/Line_follow
python3 tools/joystick_pin_probe.py
```

检查遥控器：

```bash
ros2 run line_follow remote_relay_drive_node --ros-args -p debug_inputs_only:=true
```

目标：

- `raw_active` 会随真实按键变化
- `filtered_active` 稳定，不乱跳

### 6.2 第二步：检查抢占链路

联合启动后，开 4 个终端：

```bash
ros2 topic echo /joystick_override_active
```

```bash
ros2 topic echo /joystick_motor_speed_cmd
```

```bash
ros2 topic echo /motor_speed_cmd
```

```bash
ros2 node info /motor_driver_control_node
```

目标：

- 摇杆第一次拨动时，`/joystick_override_active` 变 `true`
- `/joystick_motor_speed_cmd` 有值
- 驱动节点已订阅 `/motor_speed_cmd`、`/joystick_motor_speed_cmd`、`/joystick_override_active`

### 6.3 第三步：检查巡线开关链路

监控：

```bash
ros2 param get /line_follow_motor_model_node enabled
```

```bash
ros2 topic echo /line_follow/line_angle_deg
```

```bash
ros2 topic echo /motor_speed_cmd
```

目标：

1. 刚启动时 `enabled=false`
2. 长按巡线键后 `enabled=true`
3. 松开巡线键后 `enabled=false`
4. 松开后不应再持续出现非零巡线速度

### 6.4 第四步：检查视觉链路

视觉主监控：

```bash
ros2 topic echo /line_follow/line_angle_deg
```

```bash
ros2 topic hz /line_follow/line_angle_deg
```

调试图像：

- `/line_follow/debug_binary`
- `/line_follow/debug_detect`
- `/line_follow/debug_angle_curve`

当前默认视觉参数已针对黑线场地做保守收敛：

- `min_component_area=80`
- `max_component_width_px=120`
- `max_component_width_ratio=0.12`
- `component_intensity_limit=120.0`
- `margin=120`
- `minpix=80`
- `roi_height_ratio=0.22`

如果仍有误判，优先现场临时调：

```bash
ros2 param set /line_follow_angle_node thresh 90
ros2 param set /line_follow_angle_node component_intensity_limit 100
ros2 param set /line_follow_angle_node margin 100
```

### 6.5 第五步：检查驱动下发

监控输出：

```bash
ros2 topic echo /motor_speed_cmd
```

如果怀疑不是巡线而是别的节点在发：

```bash
ros2 topic info /motor_speed_cmd -v
```

直接手工验证参数链路：

```bash
ros2 param set /line_follow_motor_model_node enabled false
ros2 param get /line_follow_motor_model_node enabled
```

如果这一步成功，说明模型参数服务本身正常。

## 8. 常见问题

### 8.1 上电后第一次拨摇杆没反应

先看：

```bash
ros2 topic echo /joystick_override_active
ros2 topic echo /joystick_motor_speed_cmd
ros2 topic echo /motor_speed_cmd
```

如果前两个正常、最后一个不切，问题在驱动抢占链路。

### 8.2 松开巡线键后还在走

先分清楚是不是只在收 `[0.0, 0.0]`。

再查：

```bash
ros2 param get /line_follow_motor_model_node enabled
ros2 topic info /motor_speed_cmd -v
```

### 8.3 `enabled` 没关掉

先手工验证：

```bash
ros2 param set /line_follow_motor_model_node enabled false
```

如果手工能设下去，说明参数服务正常，回头查长按节点或旧版本 service。

### 8.4 节点名重复

说明你同时跑了两套。

先停 service，再杀残留：

```bash
systemctl stop line-follow-hybrid.service
pkill -f remote_long_press_start_line_follow_node
pkill -f joystick_drive_node
pkill -f line_follow_system.launch.py
pkill -f line_follow_angle_node
pkill -f line_follow_motor_model_node
pkill -f motor_driver_control_node
```

### 8.5 service 停不掉

先 kill 再 stop：

```bash
systemctl kill line-follow-hybrid.service
systemctl stop line-follow-hybrid.service
```

## 9. 最终验证清单

联合版正常工作的最低标准：

- 只有一套 `line_follow`/`joystick` 节点
- 摇杆第一次拨动就能接管
- 摇杆松开后能让权
- 长按巡线能把 `enabled` 从 `false -> true -> false`
- 视觉输出角度稳定，不被大块污渍明显拉偏
- `/motor_speed_cmd` 发布者清晰，没有未知节点混发
- `line-follow-hybrid.service` 能独立起停，不依赖旧服务

```bash
ros2 topic echo /motor_speed_cmd
```

再开一个终端观察摇杆命令：

```bash
ros2 topic echo /joystick_motor_speed_cmd
```

预期：

- 不拨摇杆时，`/joystick_override_active` 为 `false`
- 摇杆拨动某一方向时，`/joystick_override_active` 变为 `true`
- 这时真正执行的是 `/joystick_motor_speed_cmd`
- 松开摇杆后，`/joystick_override_active` 回到 `false`

### 7.3 最后再验证与遥控器并行

测试顺序建议：

1. 不动摇杆，长按遥控器前进键，确认车按遥控器逻辑运行
2. 遥控器还保持动作时，再拨动摇杆
3. 确认车辆行为立刻切到摇杆控制
4. 松开摇杆
5. 确认车辆重新回到遥控器或巡线逻辑

如果这里行为不对，优先检查：

- `/joystick_override_active`
- `/joystick_motor_speed_cmd`
- `/motor_speed_cmd`

## 9. 故障排查

### 9.1 摇杆完全没反应

先检查：

```bash
ros2 node list
ros2 topic list | grep joystick
```

再检查输入探针：

```bash
cd /userdata/dev_ws/src/originbot/Line_follow
python3 tools/joystick_pin_probe.py
```

如果探针也没有变化，优先排查：

- 接线错误
- 摇杆模块电源没接好
- 物理针脚编号和程序配置不一致

### 9.2 摇杆偶发误触发

先看：

```bash
ros2 run line_follow joystick_drive_node --ros-args -p debug_inputs_only:=true
```

如果 `raw_active` 乱跳，但 `filtered_active` 基本稳定：

- 说明软件滤波有效
- 继续增大 `debounce_activate_count` 和 `debounce_deactivate_count`

如果 `filtered_active` 也经常跳：

- 说明电平干扰已经超过当前软件滤波能力
- 需要同时检查硬件上拉/下拉和接地

### 9.3 遥控器能动，摇杆抢不过来

优先检查：

```bash
ros2 topic echo /joystick_override_active
ros2 topic echo /joystick_motor_speed_cmd
```

如果摇杆拨动时：

- `/joystick_motor_speed_cmd` 有值
- 但 `/joystick_override_active` 没变成 `true`

说明问题在摇杆占用标志链路。

如果两者都有值，但车辆行为还是没切换，继续检查：

```bash
ros2 node info /motor_driver_control_node
```

确认它已经订阅：

- `/motor_speed_cmd`
- `/joystick_motor_speed_cmd`
- `/joystick_override_active`

### 9.4 摇杆松开后车不立刻让权

先看：

```bash
ros2 topic echo /joystick_override_active
```

如果回落慢，可以适当减小：

- `debounce_deactivate_count`

但减小太多会降低抗干扰能力，需要现场折中。

### 9.5 两边都在抢驱动节点

如果你不是用联合 launch，而是手工分别启动多个节点，务必确认：

- 只有一个地方在启动 `motor_driver_control_node`

推荐做法：

- 要么只让 `line_follow_system.launch.py` 启动驱动
- 要么手工单独启动驱动，然后上层节点都加：

```bash
--ros-args -p autostart_driver_process:=false
```
