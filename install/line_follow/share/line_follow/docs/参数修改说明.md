# 调试过程中可修改的参数说明

本文整理 `Line_follow` 在部署、分阶段验证、联调过程中会用到的可调参数，便于现场调试时快速查阅。

说明：

- 本文覆盖视觉角度节点、运动模型节点、驱动通信节点，以及整系统 `launch` 暴露出的常用参数。
- 参数默认值以当前源码为准。
- 文中“常见调参方向”是现场调试建议，不代表必须修改。

单独调视觉节点，输入用 /hbmem_img，并修改几项常用检测参数：

  source /opt/ros/humble/setup.bash
  source /userdata/dev_ws/install/setup.bash

  ros2 run line_follow line_follow_angle_node \
    --ros-args \
    -p image_topic:=/hbmem_img \
    -p image_msg_type:=hbmem \
    -p line_is_white:=false \
    -p min_component_area:=200 \
    -p max_component_area:=20000 \
    -p max_component_width_px:=180 \
    -p component_intensity_limit:=90 \
    -p roi_y_start_ratio:=0.5 \
    -p blur_ksize:=5 \
    -p morph_ksize:=3 \
    -p show_debug:=false \
    -p publish_debug_image:=true \
    -p show_angle_curve:=true

  如果是整系统启动时一起改，也可以这样传：

  source /opt/ros/humble/setup.bash
  source /userdata/dev_ws/install/setup.bash

  ros2 launch line_follow line_follow_system.launch.py \
    device:=/dev/video8 \
    image_topic:=/hbmem_img \
    image_msg_type:=hbmem \
    line_is_white:=false \
    min_component_area:=200 \
    max_component_area:=20000 \
    max_component_width_px:=180.0 \
    component_intensity_limit:=90.0 \
    roi_y_start_ratio:=0.5 \
    blur_ksize:=5 \
    morph_ksize:=3 \
    publish_debug_image:=true

  运行中查看当前参数值：

  ros2 param list /line_follow_angle_node
  ros2 param get /line_follow_angle_node min_component_area

  运行中临时改“可热更新”的参数示例：

  ros2 param set /line_follow_angle_node min_component_area 300
  ros2 param set /line_follow_angle_node roi_y_start_ratio 0.55
  ros2 param set /line_follow_angle_node component_intensity_limit 80.0

## 1. 视觉角度节点参数

对应节点：

- `ros2 run line_follow line_follow_angle_node`

主要用途：

- 订阅图像话题
- 完成二值化、连通域过滤、滑动窗口检测和角度计算
- 发布 `/line_follow/line_angle_deg`、`/line_follow/steer_angle_deg`
- 发布调试图像

| 参数名 | 默认值 | 中文说明 | 常见调参方向 |
| --- | --- | --- | --- |
| `image_topic` | `/camera/image` | 输入图像话题名 | 在 RDK 部署时通常改成 `/image` |
| `line_is_white` | `false` | 目标引导线是否为白线，`false` 表示黑线白底，`true` 表示白线黑底 | 识别方向明显反了时
         优先切换这个参数 |
| `blur_ksize` | `5` | 高斯模糊核大小，用于抑制噪声 | 画面纹理多、噪声大时适当增大 |
| `thresh` | `-1` | 二值化阈值，`-1` 表示使用 Otsu 自动阈值 | 光照稳定时可手动指定阈值 |
| `morph_ksize` | `3` | 形态学开闭运算核大小，用于去噪和补小断裂 | 噪点多可适当增大，但过大会吞细线 |
| `min_component_area` | `0` | 连通域最小面积，小于该值的目标会被丢弃 | 去小噪点时增大 |
| `max_component_area` | `0` | 连通域最大面积，`0` 表示不限制 | 去大块阴影、污渍时减小到合适范围 |
| `max_component_width_px` | `0` | 连通域最大宽度，单位像素，`0` 表示不限制 | 去掉过宽黑块或大面积干扰时设置 |
| `max_component_width_ratio` | `0.0` | 连通域最大宽度占图像宽度的比例，`0` 表示不限制 | 希望参数随分辨率自适应时
         使用 |
| `component_intensity_limit` | `-1.0` | 连通域灰度强度过滤阈值，负数表示关闭 | 黑线模式下可减小以只保留更黑目标；
         误删正常线时先设为 `-1` |
| `n_windows` | `9` | 滑动窗口层数，从下向上搜索线条中心 | 视野更高时可增加 |
| `margin` | `300` | 滑动窗口半宽，单位像素 | 线条横向偏移大时增大；误跟踪干扰时减小 |
| `minpix` | `50` | 每个窗口内判定为“找到线”的最少非零像素数 | 线较细或较远时减小；噪点多时增大 |
| `kp` | `1.0` | 建议转向角 `steer_angle_deg` 的比例系数 | 主要用于调试观察，通常不是第一优先级 |
| `roi_y_start_ratio` | `0.5` | 底部直方图 ROI 起始高度比例，越小表示 ROI 越大 | 远处线条进不了底部检测区时减小到
         `0.35` 或 `0.2` |
| `show_debug` | `false` | 是否打开本地 OpenCV 调试窗口 | 仅在有桌面环境时建议开启 |
| `publish_debug_image` | `true` | 是否发布调试图像话题 | 远程 SSH 调试时建议保持开启 |
| `debug_binary_topic` | `/line_follow/debug_binary` | 二值化调试图像话题名 | 一般不改，除非要避开话题冲突 |
| `debug_detect_topic` | `/line_follow/debug_detect` | 检测结果调试图像话题名 | 一般不改 |
| `debug_angle_curve_topic` | `/line_follow/debug_angle_curve` | 角度历史曲线调试图像话题名 | 一般不改 |
| `show_angle_curve` | `true` | 是否生成角度历史曲线图像 | 不需要角度曲线时可关闭以减轻开销 |
| `angle_curve_history_size` | `240` | 曲线历史长度，单位帧 | 想观察更长时间趋势时增大 |
| `angle_curve_limit_deg` | `45.0` | 曲线显示时的纵轴角度范围 | 实际角度幅度较小时可减小，便于观察变化 |

### 1.1 视觉调试时最常改的参数

- `line_is_white`
- `thresh`
- `min_component_area`
- `max_component_area`
- `max_component_width_px`
- `max_component_width_ratio`
- `component_intensity_limit`
- `margin`
- `minpix`
- `roi_y_start_ratio`
- `publish_debug_image`

### 1.2 视觉调试经验

- 有图像但没有角度输出时，先确认 `line_is_white` 是否正确。
- 如果画面里能看到线，但节点提示检测失败，优先减小 `roi_y_start_ratio`。
- 如果调试图里有很多小碎块，增大 `min_component_area`。
- 如果大块阴影被当成目标，减小 `max_component_area` 或限制 `max_component_width_px`。
- 如果正常线条也被过滤掉，先把 `component_intensity_limit` 改成 `-1` 关闭强度过滤。

## 2. 运动模型节点参数

对应节点：

- `ros2 run line_follow line_follow_motor_model_node`

主要用途：

- 将 `/line_follow/line_angle_deg` 转成左右电机 RPM
- 发布 `/motor_speed_cmd`
- 输入超时后自动发布停车命令

| 参数名 | 默认值 | 中文说明 | 常见调参方向 |
| --- | --- | --- | --- |
| `angle_topic` | `/line_follow/line_angle_deg` | 输入视觉角度话题 | 上游改话题名时同步修改 |
| `speed_topic` | `/motor_speed_cmd` | 输出左右电机速度话题 | 下游驱动节点改话题时同步修改 |
| `publish_debug_topic` | `true` | 是否发布调试话题 `/line_follow/center_motor_rpm` 和 `/line_follow/delta_motor_r
         pm` | 联调时建议开启 |
| `max_visual_angle_deg` | `45.0` | 参与控制前允许的最大视觉角度绝对值 | 防止异常值导致速度发散 |
| `heading_gain` | `1.8` | 视觉角度到目标偏航角速度的增益 | 转向偏软时增大，转向过猛时减小 |
| `base_speed_ratio` | `0.32` | 基础前进速度占额定输出转速的比例 | 整体速度过快时减小，过慢时增大 |
| `speed_reduce_gain` | `0.55` | 角度变大时降低基础速度的幅度 | 弯道仍冲得太快时增大 |
| `min_output_rpm` | `18.0` | 输出轴最小保持转速 | 起步发抖或停转时适当增大 |
| `allow_reverse` | `true` | 急转时是否允许一侧履带反转 | 不希望原地式急转时设为 `false` |
| `command_timeout_sec` | `0.5` | 超过该时间未收到角度输入则主动停车 | 想更保守停车可减小 |
| `angle_lowpass_alpha` | `0.35` | 视觉角度低通滤波系数 | 变小更稳，变大更灵敏 |
| `angle_deadband_deg` | `1.5` | 小角度死区，单位度 | 直行抖动时增大 |
| `max_motor_rpm_step_per_sec` | `1200.0` | 电机 RPM 每秒最大变化量 | 变小更平顺，变大更跟手 |
| `track_width_m` | `0.577` | 左右履带中心距，单位米 | 这是最关键底盘参数，建议实测 |
| `drive_wheel_diameter_m` | `0.18` | 驱动轮直径，单位米 | 机械参数不准时会影响速度换算 |
| `track_pitch_m` | `0.06` | 履带节距，单位米 | 用于估算履带回路长度 |
| `track_link_count` | `24` | 履带节数 | 与节距一起影响机械换算 |
| `rated_voltage_v` | `48.0` | 电机额定电压 | 主要用于模型参数留档，通常不作为现场首调项 |
| `rated_power_w` | `400.0` | 电机额定功率 | 同上 |
| `rated_current_a` | `11.0` | 电机额定电流 | 同上 |
| `rated_motor_rpm` | `3000.0` | 电机额定转速 | 影响减速后输出转速估算 |
| `rated_motor_torque_nm` | `1.27` | 电机额定扭矩 | 用于估算减速比 |
| `no_load_current_a` | `2.0` | 电机空载电流 | 主要用于参数留档 |
| `no_load_motor_rpm` | `3300.0` | 电机空载转速 | 用于速度上限保护 |
| `rated_output_torque_nm` | `14.0` | 输出轴额定扭矩 | 与电机额定扭矩一起估算减速比 |
| `left_motor_sign` | `1.0` | 左电机方向符号 | 正装为 `1.0`，反装可设为 `-1.0` |
| `right_motor_sign` | `-1.0` | 右电机方向符号 | 当前默认用于相对安装电机 |

### 2.1 运动模型调试时最常改的参数

- `track_width_m`
- `heading_gain`
- `base_speed_ratio`
- `speed_reduce_gain`
- `allow_reverse`
- `command_timeout_sec`
- `angle_lowpass_alpha`
- `angle_deadband_deg`
- `max_motor_rpm_step_per_sec`
- `left_motor_sign`
- `right_motor_sign`

### 2.2 运动模型调试经验

- 转弯不够明显，先增大 `heading_gain`。
- 角度稍大时车仍然冲得太快，增大 `speed_reduce_gain`。
- 整体速度太快，减小 `base_speed_ratio`。
- 视觉偶尔丢帧但车不应持续冲行，减小 `command_timeout_sec`。
- 直行时履带来回轻微抽动，增大 `angle_deadband_deg` 或减小 `angle_lowpass_alpha`。
- 电机速度变化太猛，减小 `max_motor_rpm_step_per_sec`。
- 电机相对安装时，前进若不是“一正一负”，优先检查 `left_motor_sign/right_motor_sign`。

## 3. 驱动通信节点参数

对应节点：

- `ros2 run line_follow motor_driver_control_node`

主要用途：

- 订阅 `/motor_speed_cmd`
- 通过 Modbus RTU 下发左右电机转速和方向

| 参数名 | 默认值 | 中文说明 | 常见调参方向 |
| --- | --- | --- | --- |
| `serial_port` | `/dev/ttyUSB0` | 电机驱动串口设备路径 | 串口号不对时先改这个 |
| `baud_rate` | `9600` | 串口波特率 | 必须与驱动器实际配置一致 |
| `serial_timeout_sec` | `0.1` | 串口读写超时 | 通信较慢时可适当增大 |
| `speed_topic` | `/motor_speed_cmd` | 订阅的速度命令话题 | 上游修改话题时同步修改 |
| `left_slave` | `6` | 左驱动器 Modbus 站号 | 与驱动器站号配置保持一致 |
| `right_slave` | `8` | 右驱动器 Modbus 站号 | 与驱动器站号配置保持一致 |
| `min_speed_rpm` | `0` | 下发给驱动器时允许的最小转速 | 一般保持默认 |
| `max_speed_rpm` | `5000` | 下发给驱动器时允许的最大转速 | 驱动器保护或限速时可下调 |
| `auto_start` | `true` | 写速度后是否自动写入启停方向寄存器 | 一般保持开启 |

### 3.1 驱动调试时最常改的参数

- `serial_port`
- `baud_rate`
- `serial_timeout_sec`
- `left_slave`
- `right_slave`
- `max_speed_rpm`

### 3.2 驱动调试经验

- 串口打不开时先查 `serial_port` 和权限。
- 有串口但电机不动时，优先确认 `left_slave`、`right_slave`、A/B 线和驱动器模式。
- 通信偶发超时时，可适当增大 `serial_timeout_sec`。

### 4.3 驱动通信相关

| 参数名 | 默认值 | 中文说明 |
| --- | --- | --- |
| `serial_port` | `/dev/ttyUSB0` | 驱动串口设备路径 |
| `baud_rate` | `9600` | 驱动串口波特率 |

| `driver_command_timeout_sec` | `0.5` | 驱动节点自己判定速度命令超时后主动停机的时间 | 上游异常时建议保持开启 |

| `fault_reset_counter` | `0` | 人工复位驱动故障锁定的计数器，需递增设置 | 故障锁定后用于恢复 |

## 5. 推荐的现场调参顺序

1. 先确认 `/image` 和 `/hbmem_img` 都正常，再改视觉参数；若 `/hbmem_img` 存在但节点报 `incompatible QoS`，先重新编译并确认运行的是最新版节点。
2. 视觉阶段优先调 `line_is_white`、`roi_y_start_ratio`、连通域过滤参数。
3. 角度稳定后，再调 `heading_gain`、`base_speed_ratio`、`speed_reduce_gain`。
4. 最后再核对 `serial_port`、站号、波特率等驱动通信参数。

## 6. 常用命令示例

### 6.1 单独启动视觉角度节点

```bash
ros2 run line_follow line_follow_angle_node \
  --ros-args \
  -p image_topic:=/hbmem_img \
  -p image_msg_type:=hbmem \
  -p line_is_white:=false \
  -p roi_y_start_ratio:=0.35 \
  -p min_component_area:=80 \
  -p max_component_area:=40000 \
  -p max_component_width_px:=260 \
  -p component_intensity_limit:=-1 \
  -p publish_debug_image:=true \
  -p show_debug:=false
```

### 6.2 单独启动运动模型节点

```bash
ros2 run line_follow line_follow_motor_model_node \
  --ros-args \
  -p track_width_m:=0.577 \
  -p heading_gain:=1.8 \
  -p base_speed_ratio:=0.32 \
  -p speed_reduce_gain:=0.55 \
  -p allow_reverse:=true \
  -p command_timeout_sec:=0.5
```

### 6.3 单独启动驱动通信节点

```bash
ros2 run line_follow motor_driver_control_node \
  --ros-args \
  -p serial_port:=/dev/ttyUSB0 \
  -p baud_rate:=9600 \
  -p serial_timeout_sec:=0.1 \
  -p left_slave:=6 \
  -p right_slave:=8 \
  -p min_speed_rpm:=0 \
  -p max_speed_rpm:=5000 \
  -p auto_start:=true \
  -p driver_command_timeout_sec:=0.5 \
  -p write_retry_count:=2 \
  -p fail_safe_on_write_error:=true \
```

### 7.4 驱动故障锁定后的恢复命令

如果驱动节点因为连续写失败进入故障锁定，先排除串口、站号、供电问题，再执行：

```bash
ros2 param set motor_driver_control_node fault_reset_counter 1
```

如果下一次还要再次复位，就继续递增：

```bash
ros2 param set motor_driver_control_node fault_reset_counter 2
```
