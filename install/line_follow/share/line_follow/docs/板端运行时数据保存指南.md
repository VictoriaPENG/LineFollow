# 板端运行时数据保存指南

本文档针对当前板端的长按遥控巡线模式，主入口是：

```bash
ros2 run line_follow remote_long_press_start_line_follow_node
```

当前实现里，这个节点会先常驻拉起整套巡线系统，再通过长按遥控器切换：

- 手动前进
- 自动巡线
- 松开即停车

所以现场要保存的数据，不应只看单个节点，而要把下面几类信息一起留住：

- 长按遥控节点日志
- 巡线系统运行参数
- 图像和控制链路 ROS 话题
- 故障发生时的节点和参数快照

## 1. 建议保存哪些数据

建议至少保存这四类：

- 启动和运行日志
- 运行时参数快照
- ROS bag
- 故障时补充信息

如果你只保最小集合，也至少保留：

- `remote_long_press.log`
- 一份参数快照目录
- 一个 `ros2 bag` 目录

## 2. 建立本次测试目录

每次测试单独建目录：

```bash
RUN_DIR=/userdata/test_logs/$(date +%F_%H%M%S)
mkdir -p "$RUN_DIR"
```

后面的日志、参数、bag 都放这里。

## 3. 先确认当前运行链路

启动前或启动后都建议确认一遍当前链路：

```bash
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash

ros2 node list | grep line_follow
ros2 param get /line_follow_motor_model_node enabled
ros2 param get /line_follow_angle_node image_topic
ros2 param get /line_follow_angle_node image_msg_type
```

当前长按模式下，正常预期是：

- `/remote_long_press_start_line_follow_node` 在运行
- `/line_follow_angle_node` 在运行
- `/line_follow_motor_model_node` 在运行
- `/motor_driver_control_node` 在运行
- `/line_follow_motor_model_node enabled` 默认是 `False`
- 视觉默认输入通常是 `/hbmem_img` 和 `hbmem`

## 4. 保存运行日志

长按遥控巡线模式建议直接把主入口日志保存下来：

```bash
cd /userdata/dev_ws
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash

ros2 run line_follow remote_long_press_start_line_follow_node 2>&1 | tee "$RUN_DIR/remote_long_press.log"
```

这份日志里通常能看到：

- 长按节点是否正常启动
- 是否成功拉起整套巡线系统
- 遥控器长按是否被识别
- 巡线 `enabled` 是否成功切换

如果你需要同时单独记录节点列表，可以另开一个终端：

```bash
watch -n 0.5 "ros2 node list" | tee "$RUN_DIR/node_watch.log"
```

## 6. 保存图像和控制链路数据

现场最稳妥的方式还是 `ros2 bag record`。

### 6.1 推荐录制的话题

长按遥控巡线模式下，建议优先录这些：

- 原始图像：`/hbmem_img` 或 `/image`
- 调试检测图：`/line_follow/debug_detect`
- 调试二值图：`/line_follow/debug_binary`
- 角度曲线图：`/line_follow/debug_angle_curve`
- 视觉角度输出：`/line_follow/line_angle_deg`
- 电机速度命令：`/motor_speed_cmd`

如果你想把“当前是手动前进还是自动巡线”一起判断清楚，最好再补抓：

- `/line_follow/line_offset_norm`
- `/line_follow/line_offset_px`

### 6.2 录制板端默认图像链路

当前板端默认视觉输入一般是 `/hbmem_img`，所以优先用下面这条：

```bash
cd "$RUN_DIR"

ros2 bag record \
  /hbmem_img \
  /line_follow/debug_binary \
  /line_follow/debug_detect \
  /line_follow/debug_angle_curve \
  /line_follow/line_angle_deg \
  /line_follow/line_offset_norm \
  /line_follow/line_offset_px \
  /motor_speed_cmd
```

### 6.3 如果你当前改成了普通图像 `/image`

如果视觉节点实际订阅的是 `/image`，就录：

```bash
cd "$RUN_DIR"

ros2 bag record \
  /image \
  /line_follow/debug_binary \
  /line_follow/debug_detect \
  /line_follow/debug_angle_curve \
  /line_follow/line_angle_deg \
  /line_follow/line_offset_norm \
  /line_follow/line_offset_px \
  /motor_speed_cmd
```

### 6.4 最小录制集合

如果板端空间紧张，至少保留：

```bash
cd "$RUN_DIR"

ros2 bag record \
  /line_follow/debug_detect \
  /line_follow/line_angle_deg \
  /motor_speed_cmd
```

这套最小集合至少能看出：

- 视觉有没有识别到线
- 角度输出是否合理
- 电机命令是否跟着变化

## 7. 保存图像前先确认调试图像已经打开

如果你要保存 `/line_follow/debug_*`，先确认视觉节点已经在发布这些话题：

```bash
ros2 param set /line_follow_angle_node publish_debug_image true
ros2 topic list | grep /line_follow/debug
```

再检查图像话题是否真的存在：

```bash
ros2 topic list | grep -E '^/image$|^/hbmem_img$|^/line_follow/debug'
```

如果你需要确认当前到底是哪种输入图像：

```bash
ros2 param get /line_follow_angle_node image_topic
ros2 param get /line_follow_angle_node image_msg_type
```

## 8. 长按模式下建议额外保存的关键状态

因为现在巡线不是靠临时起停进程，而是靠运行时开关控制，所以建议额外把下面这些值也保存下来：

```bash
ros2 param get /line_follow_motor_model_node enabled >> "$RUN_DIR/key_params.txt"
ros2 param get /line_follow_angle_node publish_debug_image >> "$RUN_DIR/key_params.txt"
ros2 param get /line_follow_angle_node image_topic >> "$RUN_DIR/key_params.txt"
ros2 param get /line_follow_angle_node image_msg_type >> "$RUN_DIR/key_params.txt"
ros2 param get /line_follow_motor_model_node heading_gain >> "$RUN_DIR/key_params.txt"
ros2 param get /line_follow_motor_model_node base_speed_ratio >> "$RUN_DIR/key_params.txt"
ros2 param get /motor_driver_control_node driver_command_timeout_sec >> "$RUN_DIR/key_params.txt"
ros2 param get /motor_driver_control_node max_consecutive_write_errors >> "$RUN_DIR/key_params.txt"
```

这些值能帮助你判断：

- 巡线输出当时是不是打开着
- 调试图像是否真的开启
- 当前视觉输入到底是 `/hbmem_img` 还是 `/image`
- 电机控制链路有没有被配置得太激进或太保守

## 9. 出现异常时要立刻补保存什么

如果现场出现这些情况：

- 长按后退后不巡线
- 长按前进和自动巡线疑似打架
- 图像正常但角度不输出
- 视觉有输出但车不动
- 突然停车或驱动故障锁定

建议立刻补保存：

```bash
ros2 node list > "$RUN_DIR/node_list.txt"
ros2 topic list > "$RUN_DIR/topic_list.txt"
ros2 topic info /motor_speed_cmd > "$RUN_DIR/motor_speed_cmd_info.txt"
ros2 topic info /line_follow/debug_detect > "$RUN_DIR/debug_detect_info.txt"
ros2 topic info /hbmem_img > "$RUN_DIR/hbmem_img_info.txt" 2>/dev/null || true
ros2 topic info /image > "$RUN_DIR/image_info.txt" 2>/dev/null || true
```

再额外导出一份故障时参数：

```bash
bash /home/yunbo/rdk_backup/dev_ws/src/originbot/Line_follow/board_tools/save_runtime_params.sh "$RUN_DIR/params_after_fault"
```

## 10. 推荐的现场操作流程

建议至少开 3 个终端。

### 终端 1：运行长按遥控巡线节点并保存日志

```bash
RUN_DIR=/userdata/test_logs/$(date +%F_%H%M%S)
mkdir -p "$RUN_DIR"

cd /userdata/dev_ws
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash

ros2 run line_follow remote_long_press_start_line_follow_node 2>&1 | tee "$RUN_DIR/remote_long_press.log"
```

### 终端 2：录制图像和控制链路 bag

如果当前视觉输入是 `/hbmem_img`：

```bash
cd "$RUN_DIR"

ros2 bag record \
  /hbmem_img \
  /line_follow/debug_binary \
  /line_follow/debug_detect \
  /line_follow/debug_angle_curve \
  /line_follow/line_angle_deg \
  /line_follow/line_offset_norm \
  /line_follow/line_offset_px \
  /motor_speed_cmd
```

如果当前视觉输入是 `/image`：

```bash
cd "$RUN_DIR"

ros2 bag record \
  /image \
  /line_follow/debug_binary \
  /line_follow/debug_detect \
  /line_follow/debug_angle_curve \
  /line_follow/line_angle_deg \
  /line_follow/line_offset_norm \
  /line_follow/line_offset_px \
  /motor_speed_cmd
```

### 终端 3：保存参数快照和关键状态

```bash
bash /home/yunbo/rdk_backup/dev_ws/src/originbot/Line_follow/board_tools/save_runtime_params.sh "$RUN_DIR/params_start"

ros2 param get /line_follow_motor_model_node enabled > "$RUN_DIR/enabled_start.txt"
ros2 param get /line_follow_angle_node image_topic > "$RUN_DIR/image_topic.txt"
ros2 param get /line_follow_angle_node image_msg_type > "$RUN_DIR/image_msg_type.txt"
```

调参后或测试完成前，再执行一次：

```bash
bash /home/yunbo/rdk_backup/dev_ws/src/originbot/Line_follow/board_tools/save_runtime_params.sh "$RUN_DIR/params_final"
```

## 11. 如果你想直接保存成图片文件

如果目标是直接拿到 `png/jpg` 做人工检查，而不是离线回放，建议再看这份单独文档：

- [ROS图像话题保存说明.md](/home/yunbo/rdk_backup/dev_ws/src/originbot/Line_follow/Markdown/ROS图像话题保存说明.md)

当前现场最稳妥的顺序仍然是：

1. 先录 `ros2 bag`
2. 再补抓单帧图片

原因是 `bag` 更完整，能保留：

- 时间戳
- 多话题同步关系
- 手动前进和自动巡线切换时的全过程

## 13. 一句话建议

在当前长按遥控巡线模式下，最实用的保存方式是：

1. 用 `remote_long_press.log` 保住行为日志
2. 用参数快照保住运行配置
3. 用 `ros2 bag` 保住图像和控制链路
4. 故障发生时立刻再补一次参数和节点信息
