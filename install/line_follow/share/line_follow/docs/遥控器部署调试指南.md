# 遥控器部署调试指南

本文档只对应“遥控器手动控制小车前进/后退”的版本，推荐使用：

```bash
ros2 run line_follow remote_relay_drive_node
```

这份文档不再覆盖长按巡线模式。长按前进/长按后退切模式的内容，请看单独文档：

```bash
Markdown/长按遥控器巡线调试指南.md
```

## 1. 当前脚本作用

主入口：

```bash
ros2 run line_follow remote_relay_drive_node
```

兼容入口：

```bash
python3 tools/remote_relay_drive.py
```

当前行为：

- 监听 40Pin 物理针脚 `29` 和 `31`
- `29` 为前进通道
- `31` 为后退通道
- 低电平有效
- 只要前进通道有效，就持续发布前进命令
- 只要后退通道有效，就持续发布后退命令
- 两个通道都无效，或同时有效时，发布停车命令
- 节点启动时默认会自动开始保存运行日志、参数快照和 bag 记录

默认速度命令：

- 前进：

```bash
[-300.0, 300.0]
```

- 后退：

```bash
[300.0, -300.0]
```

## 2. 当前固定配置

程序里已经固定：

- `active_low = true`
- `allow_inputs_without_pull_resistors = true`

这表示：

- 当前按“低电平有效”解释遥控器继电器输入
- GPIO 库不支持 `PUD_UP/PUD_DOWN` 时，程序会打印警告后继续运行

注意：

- 这不代表悬空输入是安全的
- 只有在你确认继电器输出本身已经是稳定高低电平时，才适合保留当前配置

## 5. 运行方式

这个脚本本身不直接控制电机驱动串口，它只是往：

```bash
/motor_speed_cmd
```

发布速度命令。

所以运行前，要先启动驱动节点。

### 5.1 终端 1：启动驱动节点

```bash
cd /userdata/dev_ws
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
ros2 run line_follow motor_driver_control_node
```

### 5.2 终端 2：启动遥控器手动控制节点

```bash
cd /userdata/dev_ws
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
ros2 run line_follow remote_relay_drive_node
```

如果需要同时查看 Web 端图像，另开终端执行：

```bash
cd /userdata/dev_ws
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
ros2 launch line_follow usb_cam_web.launch.py device:=/dev/video0
```

访问地址：

- 开发板本机：`http://127.0.0.1:8091/`
- 局域网其他设备：`http://<BOARD_IP>:8091/`
- 检测图直连：`http://<BOARD_IP>:8091/stream/detect.mjpg`
- 原始相机图直连：`http://<BOARD_IP>:8091/stream/source.mjpg`

当前版本默认会自动在 `/userdata/test_logs` 下创建类似下面的目录：

```bash
/userdata/test_logs/remote_manual_2026-04-16_123456
```

目录中通常会包含：

- `session.log`
- `params_start/`
- `params_final/`
- `rosbag/`
- `motor_driver.log`

启动后预期日志里会看到类似信息：

- `relay remote drive ready`
- `forward_pin=29, reverse_pin=31`
- `active_low=True`
- `runtime capture enabled: run_dir=...`

如果不想自动记录：

```bash
ros2 run line_follow remote_relay_drive_node --ros-args -p auto_record_runtime_data:=false
```

如果只想关闭 bag，保留日志和参数快照：

```bash
ros2 run line_follow remote_relay_drive_node --ros-args -p record_rosbag:=false
```

## 6. 推荐调试顺序

不要一上来就落地跑，建议按下面顺序调试。

### 6.1 先验证驱动链路

先启动驱动节点：

```bash
cd /userdata/dev_ws
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
ros2 run line_follow motor_driver_control_node
```

再手工发前进命令：

```bash
ros2 topic pub --once /motor_speed_cmd std_msgs/msg/Float32MultiArray "{data: [-300.0, 300.0]}"
```

再发后退命令：

```bash
ros2 topic pub --once /motor_speed_cmd std_msgs/msg/Float32MultiArray "{data: [300.0, -300.0]}"
```

预期：

- 第一条命令对应一个方向运动
- 第二条命令对应相反方向运动

如果这里不对，先不要继续接遥控器脚本，优先处理：

- 电机方向参数
- 串口驱动通信
- 机械安装方向

### 6.2 再做安全输入调试

建议先架空底盘，运行安全调试模式：

```bash
cd /userdata/dev_ws
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
ros2 run line_follow remote_relay_drive_node --ros-args -p debug_inputs_only:=true
```

这个模式下：

- 只读 GPIO 输入
- 只打印输入状态
- 始终发布零速

观察日志：

- 不按遥控器时，应为：
  - `forward_active=False`
  - `reverse_active=False`
- 按前进通道时，只应出现：
  - `forward_active=True`
- 按后退通道时，只应出现：
  - `reverse_active=True`

如果这里不稳定，优先排查：

- 输入是否悬空
- 继电器输出是否是稳定高低电平
- 是否接错了物理针脚 `29` 和 `31`

### 6.3 最后验证手动前进后退

输入逻辑确认无误后，再运行正常模式：

```bash
cd /userdata/dev_ws
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
ros2 run line_follow remote_relay_drive_node
```

再开一个终端观察输出：

```bash
cd /userdata/dev_ws
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
ros2 topic echo /motor_speed_cmd
```

预期：

- 按住前进通道时，持续输出 `[-300.0, 300.0]`
- 按住后退通道时，持续输出 `[300.0, -300.0]`
- 松开后输出 `[0.0, 0.0]`
- 同时按住前进和后退时，也输出 `[0.0, 0.0]`

## 7. 常用临时调参

如果只想临时改速度，可直接启动时覆盖参数。

例如把前进后退速度都调小：

```bash
ros2 run line_follow remote_relay_drive_node --ros-args \
  -p forward_left_rpm:=-200.0 \
  -p forward_right_rpm:=200.0 \
  -p reverse_left_rpm:=200.0 \
  -p reverse_right_rpm:=-200.0
```

如果只想调输入打印频率，可改：

```bash
ros2 run line_follow remote_relay_drive_node --ros-args -p publish_hz:=5.0
```

## 8. 常见问题

### 8.1 找不到 GPIO 模块

现象：

```bash
No supported GPIO Python module found
```

处理：

1. 板端执行 `python3 -c "import Hobot.GPIO"`
2. 如果失败，安装或修复 GPIO Python 包
3. GPIO 模块未就绪前，不要继续测遥控器输入

### 8.2 输入不稳定，车乱动

先做安全调试模式，不要直接进入正常控制。

重点检查：

1. 不按键时两个输入是否都稳定为未触发
2. GPIO 输入是否悬空
3. 继电器输出是否真的是稳定高低电平
4. 接线是否接到了正确物理针脚 `29` 和 `31`

### 8.3 前进后退方向反了

先不要改遥控器脚本，先检查底盘方向定义。

直接手工发：

```bash
ros2 topic pub --once /motor_speed_cmd std_msgs/msg/Float32MultiArray "{data: [-300.0, 300.0]}"
```

如果这条命令让车后退，说明问题不在遥控器逻辑，而在底盘电机方向配置。

### 8.4 同步后板端像是在跑旧代码

优先检查：

1. `rsync` 是否使用了 `--delete`
2. 是否重新执行了 `colcon build --packages-select line_follow --executor sequential --parallel-workers 1`
3. 是否重新 `source /userdata/dev_ws/install/setup.bash`
4. 运行的是不是源码目录里的：

```bash
ros2 run line_follow remote_relay_drive_node
```

兼容运行方式仍可用：

```bash
python3 tools/remote_relay_drive.py
```

注意，这个脚本当前是从源码目录直接用 `python3` 启动，不是通过 `ros2 run` 启动。
