# 开发板同步时间与编译指南

本文档把原来散落在遥控器部署指南里的通用步骤单独摘出来，专门用于：

- 开发机代码同步到开发板
- 上位机系统时间同步到开发板
- 开发板单包编译
- 编译后环境加载

这份文档不涉及遥控器具体控制逻辑。

## 2. 开发机同步代码到开发板

推荐直接使用仓库内置同步脚本，它底层仍然调用 `rsync`，但默认不会同步本地编译产物。

### 2.1 推荐同步命令

```bash
bash /home/yunbo/rdk_backup/dev_ws/src/originbot/Line_follow/tools/sync_to_board.sh
```

说明：

- `--delete` 会删除开发板上已不存在于开发机的旧文件
- 默认排除本地编译和缓存目录：`build/`、`install/`、`log/`、`__pycache__/`、`*.pyc`
- 也会排除本地编辑器和仓库元数据目录：`.vscode/`、`.idea/`、`.git/`、`.codex/`

如需改目标地址，可传参：

```bash
bash /home/yunbo/rdk_backup/dev_ws/src/originbot/Line_follow/tools/sync_to_board.sh \
  root@192.168.127.10 \
  /userdata/dev_ws/src/originbot/Line_follow/
```

### 2.2 不删除旧文件的试传方式

如果只是临时试同步，不想删开发板旧文件，可手工执行 `rsync`，同时保留相同的排除规则：

```bash
rsync -av \
  --exclude '.vscode/' --exclude '.idea/' --exclude '.git/' --exclude '.codex/' \
  --exclude 'build/' --exclude 'install/' --exclude 'log/' \
  --exclude '__pycache__/' --exclude '*.pyc' --exclude '*.pyo' \
  /home/yunbo/rdk_backup/dev_ws/src/originbot/Line_follow/ \
  root@192.168.127.10:/userdata/dev_ws/src/originbot/Line_follow/
```

## 3. 上位机系统时间同步到开发板

如果开发板时间不准，日志时间、文件时间戳、bag 文件名和问题排查都会很乱。建议每次开始调试前，先把开发机时间同步到开发板。

### 3.1 直接用 `date` 同步时间

在开发机执行：

```bash
ssh root@192.168.127.10 "date -s '$(date '+%Y-%m-%d %H:%M:%S')'"
```

这条命令的含义是：

- 开发机先取当前本机时间
- 再通过 `ssh` 发送给开发板
- 开发板执行 `date -s` 设置系统时间

### 3.2 同步后检查

在开发机执行：

```bash
date
ssh root@192.168.127.10 date
```

预期：

- 开发机和开发板显示的时间应基本一致

### 3.3 如果开发板重启后时间又漂移

这种情况一般不是本工程问题，而是开发板本身没有可靠 RTC、NTP 没启用或网络授时不可用。

如果当前现场网络不稳定，建议每次调试前手动同步一次。

## 5. 开发板编译

RDK X5 上建议固定使用“单包 + 顺序 + 单并发”方式，避免编译卡死或内存占用过高。

### 5.1 常规编译

```bash
cd /userdata/dev_ws
source /opt/ros/humble/setup.bash
export MAKEFLAGS=-j1
colcon build --packages-select line_follow --executor sequential --parallel-workers 1
```

说明：

- `--packages-select line_follow` 只编译当前包
- `--executor sequential` 强制顺序执行
- `--parallel-workers 1` 限制并发数
- `MAKEFLAGS=-j1` 限制底层任务并发

### 5.2 改动较大时先清理再编译

先清理：

```bash
cd /userdata/dev_ws
rm -rf build/line_follow install/line_follow log/latest*
```

再重新编译：

```bash
source /opt/ros/humble/setup.bash
export MAKEFLAGS=-j1
colcon build --packages-select line_follow --executor sequential --parallel-workers 1
```

说明：

- 这里只清理 `line_follow` 相关产物
- 不会动其他包

### 5.3 如果开发板资源紧张

可先检查：

```bash
free -h
top
df -h
```

如果内存非常紧，可以临时启用 swap：

```bash
fallocate -l 2G /userdata/swapfile
chmod 600 /userdata/swapfile
mkswap /userdata/swapfile
swapon /userdata/swapfile
free -h
```

用完后关闭：

```bash
swapoff /userdata/swapfile
```

## 6. 编译后环境加载

编译完成后执行：

```bash
cd /userdata/dev_ws
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
ros2 pkg list | grep line_follow
```

每开一个新终端，都建议重新执行：

```bash
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
```

### 6.1 设置打开终端自动加载 ROS 环境

如果你希望开发板每次打开终端后自动执行：

```bash
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
```

可以把这两行写进当前用户的 `~/.bashrc`。

在开发板执行：

```bash
printf '\nsource /opt/ros/humble/setup.bash\nsource /userdata/dev_ws/install/setup.bash\n' >> ~/.bashrc
```

然后让当前终端立即生效：

```bash
source ~/.bashrc
```

### 6.2 检查是否生效

重新打开一个新终端，执行：

```bash
ros2 pkg list | grep line_follow
```

如果能直接看到 `line_follow`，说明自动加载已经生效。

### 6.3 如果后面不想自动加载

手动编辑：

```bash
vim ~/.bashrc
```

或者：

```bash
nano ~/.bashrc
```

删除下面两行即可：

```bash
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
```

## 8. 常见问题

### 8.1 同步后开发板像是在跑旧代码

优先检查：

1. `rsync` 是否使用了 `--delete`
2. 是否重新执行了 `colcon build --packages-select line_follow --executor sequential --parallel-workers 1`
3. 是否重新 `source /userdata/dev_ws/install/setup.bash`

### 8.2 开发板时间不对

先重新同步：

```bash
ssh root@192.168.127.10 "date -s '$(date '+%Y-%m-%d %H:%M:%S')'"
```

再检查：

```bash
ssh root@192.168.127.10 date
```

### 8.3 编译完成但 `ros2 run` 找不到新节点

先确认：

1. 这次是否真的重新编译了 `line_follow`
2. 当前终端是否重新执行了：

```bash
source /userdata/dev_ws/install/setup.bash
```

3. 当前包是否已被 ROS 正确识别：

```bash
ros2 pkg list | grep line_follow
```
