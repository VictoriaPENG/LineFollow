# 真实车体姿态接入教程

本文说明如何把当前 `line_follow` 工程从“仅用 USB 相机的视觉相对姿态”升级为“带真实车体姿态反馈”的巡线系统。

这里的真实车体姿态不是指绝对经纬度位置，而是至少能实时知道：

- 车体 yaw 角或 yaw 角速度
- 左右履带或左右轮实际运动量
- 车体相对地面的短时运动趋势

当前代码已经能从相机估计：

- `/line_follow/visual_heading_error_deg`
- `/line_follow/visual_lateral_error_px`
- `/line_follow/visual_lateral_error_norm`

这些量描述的是“车体相对线”的视觉误差。加入 IMU 和编码器后，系统可以进一步区分：

- 是线在画面里偏了
- 还是车体自己发生了偏航、打滑或速度不一致

## 1. 推荐硬件组合

最低可用组合：

- IMU：输出三轴角速度和三轴加速度，重点使用 yaw rate
- 左右编码器：输出左右履带或左右轮转速/里程

更完整组合：

- IMU
- 左右编码器
- 相机
- 电机驱动反馈电流或实际转速

不建议只加 IMU 不加编码器。IMU 可以提供短时姿态变化，但无法可靠知道车辆实际走了多远。履带车还容易打滑，编码器也不是完美真值，但至少能提供控制闭环的速度反馈。

## 2. ROS 话题规划

建议新增或接入以下标准话题：

```text
/imu/data                       sensor_msgs/msg/Imu
/wheel/left_velocity_rpm        std_msgs/msg/Float32
/wheel/right_velocity_rpm       std_msgs/msg/Float32
/odom                           nav_msgs/msg/Odometry
/line_follow/body_yaw_deg       std_msgs/msg/Float32
/line_follow/body_yaw_rate_deg  std_msgs/msg/Float32
/line_follow/fused_heading_error_deg std_msgs/msg/Float32
```

如果电机驱动已经能回传实际转速，优先直接使用驱动反馈；如果没有，需要给左右电机或履带轴加编码器。

## 3. 坐标系定义

必须先固定坐标约定，否则后面调参会混乱。

建议使用 ROS 常见车体坐标：

- `base_link`：车体中心
- `x`：车头前方
- `y`：车体左方
- `z`：车体上方
- yaw 正方向：逆时针，也就是车头向左转为正

相机坐标需要通过外参和车体坐标关联：

```text
camera_link -> base_link
```

如果暂时不做完整 TF，也至少要记录：

- 相机是否左右翻转
- 图像中心线相对车体中心的偏移
- 图像竖直方向相对车体前向的角度偏差

当前参数：

```yaml
angle_bias_deg: 3.36
target_offset_px: 67.7
```

就是这种简化标定。

## 4. IMU 接入步骤

### 4.1 确认 IMU 输出

启动 IMU 驱动后检查：

```bash
ros2 topic list | grep imu
ros2 topic echo /imu/data --once
```

重点看：

- `angular_velocity.z`
- `orientation`
- `linear_acceleration`

如果 IMU 没有可靠磁力计，绝对 yaw 可能会漂移，但 `angular_velocity.z` 通常仍然可用于短时偏航估计。

### 4.2 做静止零偏标定

车静止时记录 5 到 10 秒 `angular_velocity.z`，计算均值：

```text
gyro_z_bias = mean(angular_velocity.z)
```

运行时使用：

```text
yaw_rate_z = angular_velocity.z - gyro_z_bias
```

否则车辆静止时 yaw 也会慢慢漂。

### 4.3 积分得到短时 yaw

基础公式：

```text
yaw_rad += yaw_rate_z * dt
yaw_deg = yaw_rad * 180 / pi
```

注意：只靠陀螺积分会漂移，所以它适合短时姿态，不适合长期绝对方向。

## 5. 编码器接入步骤

### 5.1 左右速度转车体速度

假设左右履带线速度为：

```text
v_left
v_right
```

车体线速度：

```text
v = (v_left + v_right) / 2
```

车体 yaw 角速度：

```text
yaw_rate_odom = (v_right - v_left) / track_width_m
```

当前配置里已有：

```yaml
track_width_m: 0.577
drive_wheel_diameter_m: 0.18
```

RPM 转线速度：

```text
wheel_rps = wheel_rpm / 60
v = wheel_rps * pi * drive_wheel_diameter_m
```

如果编码器装在电机端，需要除以减速比。

### 5.2 发布 odom

建议新增节点：

```text
src/body_state_estimator_node.py
```

职责：

- 订阅 IMU
- 订阅左右编码器或驱动实际转速
- 融合得到 `yaw`、`yaw_rate`、`v`
- 发布 `/odom`
- 发布 `/line_follow/body_yaw_deg`
- 发布 `/line_follow/body_yaw_rate_deg`

## 6. 姿态融合建议

### 6.1 第一阶段：互补滤波

先不要直接上复杂 EKF。第一版用互补滤波更容易调通：

```text
yaw_rate = alpha * imu_yaw_rate + (1 - alpha) * odom_yaw_rate
yaw += yaw_rate * dt
```

推荐初值：

```yaml
imu_odom_alpha: 0.7
```

含义：

- IMU 响应快，抗编码器打滑
- 编码器长期更稳定，约束陀螺漂移

履带车打滑明显时，`alpha` 可以加大，比如 `0.8`。

### 6.2 第二阶段：robot_localization

系统跑稳后可以接入 `robot_localization` 的 `ekf_node`，融合：

- `/imu/data`
- `/wheel/odometry`

但这一步不是第一优先级。先让自研轻量节点跑通，更容易定位问题。

## 7. 控制器如何使用真实姿态

当前运动模型已经使用：

```text
command_angle_deg = heading_error_deg + offset_gain_deg * lateral_error_norm
```

加入真实姿态后，建议改成：

```text
command_angle_deg =
    visual_heading_error_deg
  + offset_gain_deg * visual_lateral_error_norm
  + yaw_rate_damping_gain * body_yaw_rate_deg
```

其中：

- `visual_heading_error_deg`：视觉看到的线方向误差
- `visual_lateral_error_norm`：视觉看到的横向偏移误差
- `body_yaw_rate_deg`：车体真实偏航角速度

`yaw_rate_damping_gain` 用于抑制车体已经在快速转动时继续过度打方向。

推荐初值：

```yaml
yaw_rate_damping_gain: 0.15
```

如果车转向抖动明显，增大到 `0.25`；如果转向变迟钝，降到 `0.08`。

## 9. 调试流程

### 9.1 先调传感器方向

车体原地向左转，观察：

```bash
ros2 topic echo /line_follow/body_yaw_rate_deg
```

如果向左转时输出为负，说明 IMU 或编码器符号反了，需要加符号参数修正。

### 9.2 再调编码器比例

让车低速直行，左右实际速度应该接近：

```bash
ros2 topic echo /wheel/left_velocity_rpm
ros2 topic echo /wheel/right_velocity_rpm
```

如果直行时两个值差很多，先解决机械或驱动标定问题，不要直接靠控制器硬补。

### 9.3 最后调融合和控制

建议顺序：

1. `offset_gain_deg = 0`，只看视觉角度 + yaw rate
2. 调 `yaw_rate_damping_gain`，让转向不过冲
3. 再逐步加 `offset_gain_deg`，让车辆回到线中心

## 10. 判断是否真正有效

有效表现：

- 车体被外力轻推偏航时，控制能更快抑制继续转动
- 线短暂丢失时，车不会马上沿最后一次视觉角度越转越大
- 左右履带轻微打滑时，速度输出变化更平滑
- 弯道进入和退出时过冲减少

无效或接错的表现：

- 车一启动就向一侧越修越偏
- 原地轻微晃动车体时电机剧烈反向
- yaw rate 静止时不接近 0
- 左右编码器直行时差值很大

遇到这些现象时，优先检查符号、单位和零偏，不要先改大控制增益。

## 11. 推荐实施顺序

1. 接入 IMU，发布 `/line_follow/body_yaw_rate_deg`
2. 在运动模型里只加 yaw rate damping
3. 接入左右编码器，发布 `/odom`
4. 做 IMU + 编码器互补滤波
5. 再考虑 `robot_localization`
6. 最后把相机外参和地面 IPM 加进来

这个顺序风险最低，每一步都能单独验证。
