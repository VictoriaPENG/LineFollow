# 整机调试指南

本文档针对当前 `line_follow` 工程的真实代码状态编写，目标是把整机调试流程统一成一套可执行步骤。

当前系统链路：

1. `hobot_usb_cam` 发布 `/image`，类型为 `sensor_msgs/msg/CompressedImage`
2. `hobot_codec_decoder` 订阅 `/image`，解码后发布 `/hbmem_img`，类型为 `hbm_img_msgs/msg/HbmMsg1080P`
3. `line_follow_angle_node` 订阅 `/hbmem_img`，输出 `/line_follow/line_angle_deg`
4. `line_follow_motor_model_node` 订阅 `/line_follow/line_angle_deg`，输出 `/motor_speed_cmd`
5. `motor_driver_control_node` 订阅 `/motor_speed_cmd`，通过 Modbus RTU 下发给左右驱动器

注意：

- 当前视觉节点默认输入是 `/hbmem_img`
- 当前视觉节点图像订阅使用传感器 QoS，兼容 `BEST_EFFORT`
- 当前电机默认配置为相对安装：前进时左右电机转速应表现为一正一负
- 当前整机 launch 已支持视觉参数、运动参数、电机方向参数、驱动参数透传

## 1. 调试前准备

### 1.1 机械与安全检查

调试前务必先做下面几项：

- 将履带架空，先不要落地调试
- 确认急停可用
- 确认电机驱动器供电正常
- 确认 RS485 接线正确
- 确认左右驱动器站号与参数一致
- 确认相机设备号正确，例如 `/dev/video8`

### 1.2 软件环境

板端常用环境命令：

```bash
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
```

如果刚同步了源码，先重新编译：

```bash
cd /userdata/dev_ws
source /opt/tros/humble/local_setup.bash
colcon build --packages-select line_follow
source install/setup.bash
```

## 2. 当前关键参数总览

### 2.1 视觉节点参数

当前 `line_follow_angle_node` 常用参数：

| 参数名 | 默认值 | 作用 |
| --- | --- | --- |
| `image_topic` | `/hbmem_img` | 视觉输入话题 |
| `image_msg_type` | `hbmem` | 输入消息类型，当前应使用 `hbmem` |
| `line_is_white` | `false` | 白线黑底或黑线白底切换 |
| `blur_ksize` | `5` | 高斯模糊核大小 |
| `thresh` | `-1` | 二值阈值，`-1` 表示 Otsu |
| `morph_ksize` | `3` | 形态学核大小 |
| `min_component_area` | `0` | 连通域最小面积 |
| `max_component_area` | `0` | 连通域最大面积，`0` 表示不限制 |
| `max_component_width_px` | `0` | 连通域最大宽度 |
| `max_component_width_ratio` | `0.0` | 连通域最大宽度比例 |
| `component_intensity_limit` | `-1.0` | 连通域灰度过滤阈值 |
| `n_windows` | `9` | 滑窗层数 |
| `margin` | `300` | 滑窗半宽 |
| `minpix` | `50` | 每层最少非零像素数 |
| `kp` | `1.0` | 仅用于调试转向建议值 |
| `roi_y_start_ratio` | `0.5` | 直方图 ROI 起始高度比例 |
| `publish_debug_image` | `true` | 是否发布调试图 |
| `show_angle_curve` | `true` | 是否生成角度曲线调试图 |

### 2.2 运动模型参数

当前 `line_follow_motor_model_node` 常用参数：

| 参数名 | 默认值 | 作用 |
| --- | --- | --- |
| `track_width_m` | `0.577` | 左右履带中心距 |
| `heading_gain` | `1.8` | 角度到偏航响应增益 |
| `base_speed_ratio` | `0.32` | 基础前进速度比例 |
| `speed_reduce_gain` | `0.55` | 转弯时降速强度 |
| `min_output_rpm` | `18.0` | 输出轴最小保持转速 |
| `allow_reverse` | `true` | 是否允许急转时一侧反转 |
| `command_timeout_sec` | `0.5` | 视觉输入超时停机时间 |
| `angle_lowpass_alpha` | `0.35` | 视觉角度低通滤波系数 |
| `angle_deadband_deg` | `1.5` | 小角度死区 |
| `max_motor_rpm_step_per_sec` | `1200.0` | RPM 每秒最大变化量 |
| `left_motor_sign` | `1.0` | 左电机方向符号 |
| `right_motor_sign` | `-1.0` | 右电机方向符号 |

说明：

- 当前默认配置适配“左右电机相对安装”的底盘
- 当前默认前进时通常会输出 `[正值, 负值]`

### 2.3 驱动节点参数

当前 `motor_driver_control_node` 常用参数：

| 参数名 | 默认值 | 作用 |
| --- | --- | --- |
| `serial_port` | `/dev/ttyUSB0` | 串口设备 |
| `baud_rate` | `9600` | 串口波特率 |
| `serial_timeout_sec` | `0.1` | 串口超时 |
| `left_slave` | `6` | 左驱动站号 |
| `right_slave` | `8` | 右驱动站号 |
| `min_speed_rpm` | `0` | 驱动最小转速限幅 |
| `max_speed_rpm` | `5000` | 驱动最大转速限幅 |
| `auto_start` | `true` | 写速度后是否自动启动 |

## 3. 推荐调试顺序

不要一上来整机落地跑。推荐固定按下面顺序调：

1. 只检查相机链路
2. 单独验证视觉节点
3. 单独验证运动模型节点
4. 单独验证驱动节点
5. 全链路架空联调
6. 低速落地测试
7. 逐步提速

## 4. 第一步：检查图像链路

### 4.1 启动相机与解码链路

```bash
ros2 launch line_follow usb_cam_web.launch.py device:=/dev/video8
```

开启后可直接在浏览器查看 Web 端图像：

```bash
# 开发板本机访问
http://127.0.0.1:8091/

# 局域网其他设备访问，把 <BOARD_IP> 替换为开发板 IP
http://<BOARD_IP>:8091/
```

常用页面：

- 四宫格调试页：`/`
- 检测图直连：`/stream/detect.mjpg`
- 原始相机图直连：`/stream/source.mjpg`

### 4.2 检查话题

```bash
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
ros2 topic list | grep -E '^/image$|^/hbmem_img$'
ros2 topic hz /image
ros2 topic info /hbmem_img -v
```

预期结果：

- `/image` 存在
- `/hbmem_img` 存在
- `/image` 频率正常
- `/hbmem_img` 发布端是 `hobot_codec_decoder`
- `/hbmem_img` 的 QoS 一般是 `BEST_EFFORT`

如果这里不通：

- `/image` 没有：先查相机设备号和 `hobot_usb_cam`
- `/hbmem_img` 没有：先查 `hobot_codec_decoder` 和 `hobot_shm`

## 5. 第二步：单独调视觉节点

### 5.1 启动视觉节点

```bash
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
ros2 run line_follow line_follow_angle_node \
  --ros-args \
  -p image_topic:=/hbmem_img \
  -p image_msg_type:=hbmem \
  -p line_is_white:=false \
  -p min_component_area:=20 \
  -p max_component_area:=4000 \
  -p max_component_width_px:=100 \
  -p component_intensity_limit:=-1.0 \
  -p roi_y_start_ratio:=0.5 \
  -p show_debug:=false \
  -p publish_debug_image:=true \
  -p show_angle_curve:=False
```

### 5.2 观察输出

```bash
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
ros2 topic echo /line_follow/line_angle_deg
ros2 topic list | grep line_follow
```

推荐同时查看调试图像：

- `/line_follow/debug_binary`
- `/line_follow/debug_detect`
- `/line_follow/debug_angle_curve`

### 5.3 视觉参数如何调

#### 场地线颜色不对

现象：

- 明明看到线，但角度一直不出来
- 二值图里线和背景颠倒

调整：

- 黑线白底：`line_is_white:=false`
- 白线黑底：`line_is_white:=true`

#### 噪点太多，滑窗乱跳

现象：

- `debug_binary` 里到处都是散点
- `debug_detect` 里滑窗经常偏离目标线

调整顺序：

1. 适当增大 `blur_ksize`
2. 适当增大 `morph_ksize`
3. 增大 `min_component_area`
4. 减小 `max_component_area`
5. 减小 `max_component_width_px`

#### 线条太远，底部检测不到

现象：

- 日志提示 `line not found in bottom ROI`
- 下半部分看不到明显目标，远处才有线

调整：

- 减小 `roi_y_start_ratio`

推荐尝试：

- `0.5 -> 0.35 -> 0.2`

#### 直线太宽或干扰块太大

现象：

- 黑色大片污渍被当成线
- 阴影或地面花纹被保留下来

调整：

- 减小 `max_component_width_px`
- 减小 `max_component_width_ratio`
- 适当减小 `max_component_area`
- 黑线场景可减小 `component_intensity_limit`

#### 滑窗跟踪不稳定

现象：

- 某些层能看到线，但滑窗经常丢
- 弯道时跟踪容易断

调整：

- 增大 `margin`
- 适当减小 `minpix`
- 必要时增加 `n_windows`

## 6. 第三步：单独调运动模型节点

### 6.1 启动运动模型节点

```bash
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
ros2 run line_follow line_follow_motor_model_node \
  --ros-args \
  -p track_width_m:=0.577 \
  -p heading_gain:=1.8 \
  -p base_speed_ratio:=0.32 \
  -p speed_reduce_gain:=0.55 \
  -p allow_reverse:=true \
  -p left_motor_sign:=1.0 \
  -p right_motor_sign:=-1.0 \
  -p command_timeout_sec:=0.5 \
  -p angle_lowpass_alpha:=0.35 \
  -p angle_deadband_deg:=1.5 \
  -p max_motor_rpm_step_per_sec:=1200.0
```

### 6.2 观察速度输出

```bash
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
ros2 topic echo /motor_speed_cmd
```

预期：

- 直行时左右电机绝对值接近
- 对于相对安装电机，直行前进通常表现为一正一负
- 大角度转弯时，允许一侧反转时可能出现更大速度差

### 6.3 运动参数如何调

#### 转向偏软

现象：

- 车已经偏离很多，但转向不明显

调整：

- 先增大 `heading_gain`

#### 转向过猛

现象：

- 车左右来回摆
- 一有角度就大幅修正

调整顺序：

1. 减小 `heading_gain`
2. 减小 `angle_lowpass_alpha`
3. 增大 `angle_deadband_deg`
4. 减小 `max_motor_rpm_step_per_sec`

#### 直行轻微抖动

现象：

- 线基本居中，但履带不停轻微抽动

调整顺序：

1. 增大 `angle_deadband_deg`
2. 减小 `angle_lowpass_alpha`
3. 减小 `max_motor_rpm_step_per_sec`

建议起点：

- `angle_deadband_deg: 1.5 -> 2.0 -> 3.0`
- `angle_lowpass_alpha: 0.35 -> 0.25`
- `max_motor_rpm_step_per_sec: 1200 -> 800`

#### 速度变化太猛

现象：

- 弯道前后履带转速突变明显
- 恢复到线后突然猛加速

调整：

- 减小 `max_motor_rpm_step_per_sec`

#### 车速整体太快

调整：

- 减小 `base_speed_ratio`

#### 弯道仍然冲太快

调整：

- 增大 `speed_reduce_gain`

#### 电机方向不对

现象：

- 直行输出不是你期望的符号方向
- 左右电机前进方向与机械安装不一致

调整：

- `left_motor_sign:=1.0` 或 `-1.0`
- `right_motor_sign:=1.0` 或 `-1.0`

一般原则：

- 正装电机常用 `1.0`
- 反装电机常用 `-1.0`
- 你当前这台车默认是 `left_motor_sign:=1.0 right_motor_sign:=-1.0`

## 7. 第四步：单独调驱动节点

### 7.1 启动驱动节点

```bash
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
ros2 run line_follow motor_driver_control_node \
  --ros-args \
  -p serial_port:=/dev/ttyUSB0 \
  -p baud_rate:=9600 \
  -p serial_timeout_sec:=0.1 \
  -p left_slave:=6 \
  -p right_slave:=8 \
  -p min_speed_rpm:=0 \
  -p max_speed_rpm:=5000 \
  -p auto_start:=true \
  -p driver_command_timeout_sec:=0.5 \
  -p write_retry_count:=2 \
  -p fail_safe_on_write_error:=true \
  -p max_consecutive_write_errors:=3
```

### 7.2 手工发速度验证

#### 验证前进

对于当前相对安装电机，先发：

```bash
ros2 topic pub --once /motor_speed_cmd std_msgs/msg/Float32MultiArray "{data: [-300.0, 300.0]}"
```

预期：

- 两侧履带都表现为向前

#### 验证差速

```bash
ros2 topic pub --once /motor_speed_cmd std_msgs/msg/Float32MultiArray "{data: [450.0, -200.0]}"
```

预期：

- 左右速度明显不同

#### 验证原地式反向运动

```bash
ros2 topic pub --once /motor_speed_cmd std_msgs/msg/Float32MultiArray "{data: [300.0, 300.0]}"
```

预期：

- 对于相对安装电机，这通常对应两侧履带反向运动

如果这里不对：

- 先不要继续调视觉参数
- 先修正 `left_motor_sign/right_motor_sign`
- 如果符号对但物理左右对应错，再检查 `left_slave/right_slave`

  speed_reduce_gain:=0.55 \
  angle_lowpass_alpha:=0.35 \
  angle_deadband_deg:=1.5 \
  max_motor_rpm_step_per_sec:=1200.0 \
  allow_reverse:=true \
  left_slave:=6 \
  right_slave:=8 \
  show_debug:=false \
  publish_debug_image:=true \
  show_angle_curve:=False \
  line_is_white:=false \

  max_component_area:=4000 \

联调时建议同时开 3 个观察口：

```bash
ros2 topic echo /line_follow/line_angle_deg
ros2 topic echo /motor_speed_cmd
ros2 topic info /hbmem_img -v
```

联调时你要看：

- 有线时 `/line_follow/line_angle_deg` 持续输出
- `/motor_speed_cmd` 会随角度变化
- 直行时速度符号符合你底盘机械方向
- 视觉丢失后在 `command_timeout_sec` 时间后自动停机

### 8.1 整机运行时直接修改参数

整机已经跑起来后，不需要停掉 `ros2 launch` 再重新启动，也可以直接改一部分参数。

先确认当前节点名：

```bash
ros2 node list | grep line_follow
```

当前整机 launch 默认节点名是：

- `line_follow_angle_node`
- `line_follow_motor_model_node`
- `motor_driver_control_node`

先看当前参数值：

```bash
ros2 param get line_follow_angle_node roi_y_start_ratio
ros2 param get line_follow_motor_model_node heading_gain
ros2 param get motor_driver_control_node max_speed_rpm
```

直接修改参数：

```bash
ros2 param set line_follow_angle_node roi_y_start_ratio 0.35
ros2 param set line_follow_angle_node min_component_area 120
ros2 param set line_follow_motor_model_node heading_gain 2.2
ros2 param set line_follow_motor_model_node base_speed_ratio 0.24
ros2 param set motor_driver_control_node max_speed_rpm 3200
```

建议边改边看：

```bash
ros2 topic echo /line_follow/line_angle_deg
ros2 topic echo /motor_speed_cmd
```

推荐现场操作顺序：

1. 先架空整机运行 `ros2 launch line_follow line_follow_system.launch.py ...`
2. 用 `ros2 param get` 记下当前值
3. 每次只改 1 个参数
4. 每次改完观察 3 到 5 秒，再决定下一步
5. 确认有效后，再把最终参数写回 launch 命令或参数文件

### 8.1.1 板端实际操作流程

下面给出一套可以直接在板端照着执行的流程，默认你在板端有 3 个终端。

终端 1：启动整机

```bash
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
ros2 launch line_follow line_follow_system.launch.py \
  device:=/dev/video8 \
  image_topic:=/hbmem_img \
  image_msg_type:=hbmem \
  serial_port:=/dev/ttyUSB0 \
  line_is_white:=false \
  roi_y_start_ratio:=0.50 \
  min_component_area:=80 \
  heading_gain:=1.8 \
  base_speed_ratio:=0.22 \
  max_speed_rpm:=3200
```

终端 2：观察关键输出

```bash
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
ros2 topic echo /line_follow/line_angle_deg
```

如果还要看速度，再开一个终端：

```bash
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
ros2 topic echo /motor_speed_cmd
```

终端 3：运行时调参

先记录原值：

```bash
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
ros2 param get line_follow_angle_node roi_y_start_ratio
ros2 param get line_follow_angle_node min_component_area
ros2 param get line_follow_motor_model_node heading_gain
ros2 param get line_follow_motor_model_node base_speed_ratio
ros2 param get motor_driver_control_node max_speed_rpm
```

再逐项调整：

```bash
ros2 param set line_follow_angle_node roi_y_start_ratio 0.35
ros2 param set line_follow_angle_node min_component_area 120
ros2 param set line_follow_motor_model_node heading_gain 2.2
ros2 param set line_follow_motor_model_node base_speed_ratio 0.24
ros2 param set motor_driver_control_node max_speed_rpm 2800
```

每改一次都做这 4 件事：

1. 观察 `/line_follow/line_angle_deg` 是否更稳定
2. 观察 `/motor_speed_cmd` 是否更平顺
3. 架空确认履带方向和速度变化正确
4. 记录“改前值 -> 改后值 -> 现象”

推荐的板端调参节奏：

1. 先调视觉：`line_is_white`、`roi_y_start_ratio`、`min_component_area`
2. 再调控制：`heading_gain`、`base_speed_ratio`
3. 最后调保护：`max_speed_rpm`、`command_timeout_sec`

### 8.1.2 回滚命令

如果某次运行时调参后效果变差，可以直接把参数改回去。

示例回滚命令：

```bash
ros2 param set line_follow_angle_node roi_y_start_ratio 0.50
ros2 param set line_follow_angle_node min_component_area 80
ros2 param set line_follow_motor_model_node heading_gain 1.8
ros2 param set line_follow_motor_model_node base_speed_ratio 0.22
ros2 param set motor_driver_control_node max_speed_rpm 3200
ros2 param set motor_driver_control_node fault_reset_counter 1
```

如果你在本轮调试前没有手抄原值，可以先查当前值，再决定是否重启整机恢复 launch 启动值：

```bash
ros2 param get line_follow_angle_node roi_y_start_ratio
ros2 param get line_follow_motor_model_node heading_gain
ros2 param get motor_driver_control_node max_speed_rpm
```

需要整机回到 launch 初始值时，最稳妥的回滚方式是：

1. `Ctrl+C` 停掉当前 `ros2 launch`
2. 重新执行同一条 launch 启动命令
3. 不再重复刚才那组 `ros2 param set`

### 8.2 哪些参数可以运行时生效

视觉节点 `line_follow_angle_node`：

- 已经在图像回调里逐帧读取参数，所以算法类参数可以直接生效。
- 常用可运行时修改参数：`line_is_white`、`thresh`、`min_component_area`、`max_component_area`、`max_component_width_px`、`max_component_width_ratio`、`component_intensity_limit`、`margin`、`minpix`、`roi_y_start_ratio`、`show_debug`、`publish_debug_image`、`show_angle_curve`。
- 不建议运行时修改：`image_topic`、`image_msg_type`、调试图像话题名。这些涉及订阅器或发布器创建，通常应重启节点。

运动模型节点 `line_follow_motor_model_node`：

- 现在已经增加参数回调，下面这些参数在整机运行时可直接修改：`heading_gain`、`lateral_gain`、`base_speed_ratio`、`speed_reduce_gain`、`min_output_rpm`、`allow_reverse`、`command_timeout_sec`、`offset_timeout_sec`、`angle_lowpass_alpha`、`angle_deadband_deg`、`max_motor_rpm_step_per_sec`、`track_width_m`、`drive_wheel_diameter_m`、`track_pitch_m`、`track_link_count`、`rated_motor_rpm`、`rated_motor_torque_nm`、`no_load_motor_rpm`、`rated_output_torque_nm`、`left_motor_sign`、`right_motor_sign`。
- 不建议运行时修改：`angle_topic`、`offset_topic`、`speed_topic`、`publish_debug_topic`。

驱动节点 `motor_driver_control_node`：

- 现在已经增加参数回调，下面这些参数在整机运行时可直接修改：`serial_port`、`baud_rate`、`serial_timeout_sec`、`left_slave`、`right_slave`、`min_speed_rpm`、`max_speed_rpm`、`auto_start`、`driver_command_timeout_sec`、`write_retry_count`、`fail_safe_on_write_error`、`max_consecutive_write_errors`、`fault_reset_counter`。
- 其中修改 `serial_port`、`baud_rate`、`serial_timeout_sec` 时，节点会先尝试打开新串口，打开失败则本次参数修改直接报错，不会覆盖旧配置。
- 当连续写失败达到 `max_consecutive_write_errors` 后，驱动节点会进入故障锁定；需要人工执行 `ros2 param set motor_driver_control_node fault_reset_counter 1` 这类命令递增复位计数器后才会恢复。
- 不建议运行时修改：`speed_topic`。

### 8.3 本次用于支持运行时调参的具体代码

运动模型节点核心代码：

```python
from rcl_interfaces.msg import SetParametersResult

self.add_on_set_parameters_callback(self._on_set_parameters)

def _on_set_parameters(self, params):
    static_params = {"angle_topic", "offset_topic", "speed_topic", "publish_debug_topic"}
    overrides = {}
    for param in params:
        if param.name in static_params:
            return SetParametersResult(
                successful=False,
                reason=f"{param.name} requires node restart because publishers/subscriptions are already created",
            )
        overrides[param.name] = param.value

    self._refresh_runtime_parameters(overrides)
    return SetParametersResult(successful=True)
```

驱动节点核心代码：

```python
from rcl_interfaces.msg import SetParametersResult

self.add_on_set_parameters_callback(self._on_set_parameters)

def _on_set_parameters(self, params):
    candidate_ser = None
    if reopen_needed:
        candidate_ser = self._open_serial(new_port, new_baud, new_timeout)
        if candidate_ser is None:
            return SetParametersResult(successful=False, reason="failed to reopen serial")

    if reset_requested:
        self._clear_fault()
    return SetParametersResult(successful=True)
```

## 9. 第六步：落地低速测试

只有架空测试通过后再落地。

落地第一轮建议：

- 把 `base_speed_ratio` 先降到 `0.20 ~ 0.25`
- 必要时把 `max_motor_rpm_step_per_sec` 降到 `800`
- 保持 `show_debug:=false`，只看 ROS 话题

推荐第一轮低速落地参数：

```bash
base_speed_ratio:=0.22
heading_gain:=1.6
speed_reduce_gain:=0.60
angle_lowpass_alpha:=0.25
angle_deadband_deg:=2.0
max_motor_rpm_step_per_sec:=800.0
```

测试通过后再逐步加速：

1. 先加 `base_speed_ratio`
2. 再微调 `heading_gain`
3. 最后再减小 `angle_deadband_deg` 或增大 `angle_lowpass_alpha`

## 10. 常见故障与处理

### 10.1 `/hbmem_img` 有发布，但视觉节点收不到

执行：

```bash
ros2 topic info /hbmem_img -v
```

如果看到：

- 发布端是 `BEST_EFFORT`
- 订阅端是 `RELIABLE`

说明板端跑的还是旧版本节点，需要重新编译并重新 source。

### 10.2 节点报 `image convert failed`

说明 `HbmMsg1080P` 字段或图像数据布局与预期不一致，需要查看日志里的字段名提示继续修正转换逻辑。

### 10.3 有角度，但速度不平顺

优先调：

- `angle_deadband_deg`
- `angle_lowpass_alpha`
- `max_motor_rpm_step_per_sec`

### 10.4 视觉稳定，但车跑偏

优先调：

- `heading_gain`
- `track_width_m`
- `left_motor_sign/right_motor_sign`
- `left_slave/right_slave`

### 10.5 手工发速度时方向不对

优先排查顺序：

1. `left_motor_sign/right_motor_sign`
2. `left_slave/right_slave`
3. 电机物理接线和安装方向

## 11. 推荐现场调参方法

推荐每次只改一类参数，不要一口气全改。

推荐顺序：

1. 先把图像链路和视觉检测调通
2. 再把电机方向和手工速度命令调通
3. 再调 `heading_gain`
4. 再调 `base_speed_ratio` 和 `speed_reduce_gain`
5. 最后调 `angle_lowpass_alpha`、`angle_deadband_deg`、`max_motor_rpm_step_per_sec`

一个实用原则：

- 先让车“方向对、不会冲车、不会乱抖”
- 再追求“更快、更灵活、更贴线”

## 12. 建议保留的调试窗口

整机联调时建议至少保留以下观测项：

- `/line_follow/line_angle_deg`
- `/motor_speed_cmd`
- `/line_follow/debug_detect`
- `/line_follow/debug_binary`
- `/line_follow/debug_angle_curve`

如果这 5 项都能解释当前行为，现场调试效率会高很多。


## 13. 新增功能与建议

本次额外补充了 4 个现场安全相关功能：

- 驱动节点增加 `driver_command_timeout_sec`，即使上游异常，驱动节点自己也会超时主动停车。
- 驱动节点增加 `write_retry_count`、`fail_safe_on_write_error`、`max_consecutive_write_errors`，写寄存器失败时会先急停，再在连续失败达到阈值后故障锁定。
- 视觉节点现在支持运行时打开或关闭调试图像发布器，`publish_debug_image` 和调试图像话题名切换后可立即生效。
- 提供参数快照脚本 `board_tools/save_runtime_params.sh`，可以把 3 个节点当前参数导出成 YAML。

板端保存当前参数示例：

```bash
source /opt/ros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
bash /userdata/dev_ws/src/originbot/Line_follow/board_tools/save_runtime_params.sh /userdata/runtime_params_$(date +%Y%m%d_%H%M%S)
```
