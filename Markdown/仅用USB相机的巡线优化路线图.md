# 仅用 USB 相机的巡线优化路线图

本文针对当前 `line_follow` 工程在“只有一个 USB 相机、没有 IMU、没有里程计、没有编码器闭环”的硬件条件下，给出一份务实的优化路线图。

目标不是把系统包装成“高阶全状态轨迹跟踪”，而是在现有硬件约束下，把巡线稳定性、抗抖能力和可调试性继续往上推。

## 结论先说

当前方案的大方向是对的：

- 相机图像提线
- 从图像中估计线的角度和偏移
- 用差速控制让底盘沿线前进

这条路线在单 USB 相机场景下是合理主线。

但当前实现还不是这个硬件条件下的最优解，仍然有比较明确的 5 个升级方向，而且都不要求增加新传感器。

## 当前系统的主要限制

在只有单相机时，系统天然缺少下面这些信息：

- 车体真实航向
- 车体真实速度
- 车体短时姿态变化
- 车体与线之间到底是谁在动

因此你现在做不到严格意义上的“全状态轨迹跟踪”。

但这并不意味着只能停留在当前版本。你仍然可以从视觉信息挖出更多结构，再把控制做得更聪明。

## 优化优先级总览

按收益优先级，建议顺序如下：

1. 让视觉节点输出更多轨迹信息，而不只是单个角度
2. 把控制从“单角度差速”升级成“预瞄式控制”
3. 加入基于曲率和检测质量的动态调速
4. 接入相机标定与去畸变
5. 把视觉参数调试从“拍脑袋试”升级成“标准化流程”

下面逐项展开。

## 1. 升级视觉输出信息量

### 当前问题

目前视觉节点主要输出：

- `line_angle_deg`
- `line_offset_px`
- `line_offset_norm`

这对于“能跑起来”够用，但对于“跑得更稳”信息量还是偏少。

控制器实际上只拿到了一个很压缩的结果：当前线相对车头偏了多少。

这会导致两个问题：

- 无法区分近处误差和远处趋势
- 无法显式利用轨迹曲率做控制和限速

### 建议改法

在视觉节点里保留现有角度输出，同时新增：

- 中心线采样点序列
- 近场航向角
- 远场航向角
- 局部曲率估计
- 预瞄点坐标

建议修改位置：

- `src/angle_node.py`

建议输出的话题或内部数据结构：

- `/line_follow/centerline_points`
- `/line_follow/lookahead_point`
- `/line_follow/line_curvature`
- `/line_follow/near_heading_deg`
- `/line_follow/far_heading_deg`

### 收益

- 控制器不再只盯着单帧单角度
- 可以更早预判弯道
- 能把“当前偏差”和“前方趋势”分开处理

### 为什么优先级最高

因为后续所有控制升级都建立在“视觉信息更丰富”这个前提上。

如果上游仍然只给单个角度，控制器再复杂也发挥不出来。

## 2. 把控制升级成预瞄式控制

### 当前问题

当前控制基本是：

- 角度越大
- 左右差速越大

这类控制简单直接，但容易有两个典型副作用：

- 近场抖动直接反映到履带速度
- 遇到弯道时容易修正滞后

### 建议改法

在现有硬件条件下，不建议直接跳到复杂 MPC。

更现实的做法是上一个简化版预瞄控制，例如：

- Pure Pursuit 简化版
- 近场角度 + 远场角度双环控制

建议做法：

- 从中心线中取一个预瞄点
- 根据预瞄点相对车体中心的位置来算目标转向强度
- 保留左右差速输出形式，但差速不再只由单角度决定

建议修改位置：

- `src/motor_model_node.py`

如果你不想把现有文件改得过于臃肿，也可以新增：

- `src/path_tracker_node.py`

### 收益

- 减少“看见一点偏差就猛打方向”的问题
- 弯道进入更平滑
- 对静止引导线的跟踪更自然

### 为什么排第二

因为你没有 IMU 和里程计，预瞄控制已经是单相机场景里非常有性价比的一步。

它不要求额外传感器，但往往比单角度差速稳得多。

## 3. 加入基于曲率和检测质量的动态调速

### 当前问题

当前速度策略以固定 `base_motor_rpm` 为主，再叠加差速修正。

这会带来一个典型问题：

- 直线速度够快时，弯道可能过冲
- 弯道速度调慢后，直线又显得偏保守

### 建议改法

让速度不再固定，而是根据视觉结果动态变化。

最值得优先加入的调速依据有两个：

- 曲率大小
- 检测稳定度

可以按下面逻辑做：

- 直线段：提高基础速度
- 曲率变大：自动降速
- 检测置信度下降：进一步降速
- 连续丢线：最低速保底或停车

可新增的控制量：

- `target_base_rpm`
- `curvature_speed_scale`
- `detection_confidence_speed_scale`

建议修改位置：

- `src/motor_model_node.py`

### 收益

- 直线更快
- 弯道更稳
- 检测不可靠时不容易突然冲出去

### 为什么排第三

因为速度策略通常是“稳定性放大器”。

同一套视觉和控制，如果速度调度合理，整体观感会好很多。

## 4. 接入相机标定与去畸变

### 当前问题

USB 相机尤其是广角镜头时，图像畸变会明显影响：

- 线条真实几何形状python3 tools/usb_camera_calibration/generate_chessboard.py \
  --cols 9 \
  --rows 6 \
  --square-size-mm 25 \
  --output-dir tools/usb_camera_calibration/output/pattern
- 图像边缘角度判断
- 偏移量稳定性

如果相机没标定，视觉算法有时候不是在跟真实的线，而是在跟“被镜头拉弯的线”。

### 建议改法

把你已经准备好的标定工具接进主流程：

- 用标定脚本生成 `camera_calibration.json`
- 在视觉节点启动时读取标定参数
- 在 `make_binary(...)` 之前先做去畸变

建议修改位置：

- `src/angle_node.py`
- `config/line_follow_params.yaml`

建议新增参数：

- `use_camera_calibration`
- `camera_calibration_file`
- `undistort_crop_to_roi`

### 收益

- 线的几何形状更接近真实
- 图像边缘不容易出现错误角度
- 后续控制参数更容易稳定下来

### 为什么不是第一优先级

因为如果当前相机视场较窄、线主要出现在画面中间，标定带来的提升可能不如“控制逻辑升级”那么明显。

但从工程质量角度，它依然值得做。

## 5. 建立标准化视觉调参流程

### 当前问题

现在很多巡线问题，本质上不是算法不行，而是参数没有以标准流程调出来。

典型表现：

- 阈值今天调好了，明天换光照就坏
- ROI 改一点，整体效果大变
- `heading_gain` 和 `base_motor_rpm` 互相耦合，越调越乱

### 建议改法

把调参顺序固定下来，不再随机试。

推荐顺序：

1. 先固定相机参数：亮度、曝光、分辨率
2. 再调视觉分割：`line_is_white`、`thresh`、`morph_ksize`
3. 再调 ROI：`roi_bottom_offset_ratio`、`roi_height_ratio`
4. 再调滑窗：`margin`、`minpix`
5. 最后调控制：`heading_gain`、`base_motor_rpm`、`angle_deadband_deg`

同时建议：

- 每次只改一类参数
- 保留一组“基线参数”
- 记录每次改动对应现象

建议依托现有工具：

- `tools/opencv_line_verify.py`
- `tools/monitor_runtime.py`
- `/line_follow/debug_binary`
- `/line_follow/debug_detect`

### 收益

- 调参效率大幅提升
- 能更快定位问题是视觉侧还是控制侧
- 参数不会越改越乱

### 为什么它也很重要

因为在单相机巡线里，工程调参质量本身就是系统性能的一部分。

## 推荐实施顺序

如果只按性价比排序，建议这样落地：

1. 先做标准化调参流程
2. 再把视觉输出升级成“中心线 + 预瞄信息”
3. 再把控制升级成预瞄式控制
4. 再加动态调速
5. 最后接入标定去畸变并重新整体验证

如果你希望尽快看到“车走得更稳”，那更激进一点的顺序可以是：

1. 视觉输出升级
2. 预瞄控制
3. 动态调速
4. 标定去畸变
5. 标准化调参沉淀成文档

## 不建议优先做的事

在当前硬件条件下，不建议优先投入这些方向：

- 一开始就上 MPC
- 在没有状态观测的情况下硬做复杂模型控制
- 只改控制器，不改视觉输出
- 在图像质量不稳定时先卷复杂算法

原因很简单：

- 你缺少 IMU 和里程计，复杂控制器拿不到足够状态
- 上游视觉信息太贫时，下游控制再高级也会吃亏
- 图像侧没稳住时，控制侧经常是在放大噪声

## 最终建议

在“只有一个 USB 相机”的前提下，你当前方案不是终点，但已经站在正确路线附近。

最值得做的，不是幻想把系统直接变成完整高阶轨迹跟踪，而是按下面这条现实路线升级：

- 让视觉输出更丰富
- 让控制有预瞄能力
- 让速度跟着曲率和稳定度变化
- 让图像几何更可靠
- 让调参流程标准化

如果按这条路线推进，你不加新硬件，也仍然有机会把当前巡线效果明显再拉高一截。
